# 모멘텀 필터 coverage gate 미구현 — SPEC_12 §4-4

**발견**: 2026-08-11, `docs/검토/f_pbr_ma200_median_split.md` §5 후속 확인 중
**현재 영향**: **없음** (실측 전 구간 문턱 미달). 안전장치가 없다는 것이 문제다.
**분류**: 미구현 안전장치 (버그 아님, 설계된 정책이 코드에 없음)

---

## 문제 요약

SPEC_12 §4-4는 이력 부족 종목의 자동 통과를 **의도된 정책**으로 확정하면서, 동시에
그 부작용을 막을 **coverage gate**를 정의했다.

```
전체 정상 계산 비율                    >= 95%
특정 구간 정상 계산 비율 < 85%          -> 경고
데이터부족 통과가 포트폴리오의 10% 초과 -> 판정 보류
```

**이 세 조건을 검사하는 코드가 없다.** grep으로 확인한 결과 `momentum_criteria.py`·
`run_ablation.py`·`run_daily_nav.py` 어디에도 임계값 비교나 경고 발화가 없다.

게이트 자체가 SPEC에 `(기본값 — 사용자 확정 필요)`로 표기돼 있어 **사용자 확정 단계에서
멈춘 채 구현으로 넘어가지 않은 것**으로 보인다.

## 왜 자동 통과가 일어나는가 (정상 동작)

`momentum_criteria.py::_classify_gap`:

```python
if px.index.min() > window_dates[0]:
    return CriterionResult(True, None, 'passed_insufficient_data', n_obs, 'insufficient')
```

HardFilter는 상장 6개월부터 허용하는데 MA200은 약 9~10개월, 52주 고가는 약 12개월,
Family D는 13~19개월 이력이 필요하다. 그 사이 구간의 신규상장 종목은 **신호가 좋아서가
아니라 자료가 없어서** 통과한다. SPEC_12 §4-4가 이미 명시한 사실이고, 이 fail-open은
하위호환을 위해 의도적으로 선택된 것이다(2026-07-23 실측: 이 구분이 없으면 신규상장이
전부 `invalid`로 오분류돼 실행이 중단됨).

## 진단 로그가 게이트 판정에 쓸 수 없는 형태다

`MomentumCriterionFilter._write_diagnostics`는 `data_status_counts`를
**유니버스 전체**(랭킹 이전, 모멘텀 단계 평가 대상) 기준으로만 집계한다.

그런데 게이트의 세 번째 조건은 **포트폴리오**(최종 편입 N종목) 기준이다.
**분자·분모가 모두 기록되지 않으므로, 현 산출물만으로는 게이트를 사후 검증할 수도 없다.**
아래 실측은 holdings tape에서 `ma200_score` 결측을 proxy로 역산한 것이다.

## 실측 (F_pbr_ma200, 반기 21구간)

| 구간 | n=20 | n=13 | 해당 종목 |
|---|---:|---:|---|
| 2018-04-04 | 1/20 = 5.0% | 1/13 = 7.7% | 하림지주(#3) |
| 2020-04-03 | **2/20 = 10.0%** | 1/13 = 7.7% | 펌텍코리아(#11), 에이에프더블류(#18) |
| 나머지 19구간 | 0% | 0% | — |

- 문턱은 "10% **초과**"이므로 최대치인 2020-04의 10.0%도 **위반이 아니다.**
- **채택된 n=13에서는 7.7%로 더 안전하다** (#18이 컷 밖으로 나감).
- 즉 **지금까지의 어떤 판정도 이 문제로 오염되지 않았다.**

## 그럼에도 남는 위험

통과율이 낮은 구간일수록 오염 비율이 올라가는 **구조**다. 2020-04는 모멘텀 통과율이
12.9%(전 구간 최저)였고, 바로 그 구간에서 자동 통과 비율이 최고치를 찍었다. 우연이 아니다 —
신호 통과 종목이 줄어도 이력 부족 통과는 줄지 않으므로 상대 비중이 커진다.

더 심한 폭락이나 더 긴 창을 쓰는 criterion(52주 고가 = 12개월, Family D = 13~19개월)에서는
문턱을 넘을 수 있다. **넘어도 아무도 알려주지 않는 것이 현재 상태다.**

## 해결 방안

| 방안 | 내용 | 비고 |
|---|---|---|
| **A. 게이트 구현** (권장) | 포트폴리오 확정 후 `insufficient` 통과 비율을 계산해 문턱 초과 시 경고·판정 보류 | SPEC 의도 그대로. 기존 결과 불변 |
| B. 진단 확장 | `_write_diagnostics`에 포트폴리오 단위 카운트 추가 | A의 선행 조건. 사후 검증 가능해짐 |
| C. fail-closed 전환 | 이력 부족 종목을 탈락 처리 | **기존 전 결과가 바뀐다.** 하위호환 파기 |
| D. 최소 관측일수 요건 | HardFilter 상장 기간을 criterion 창에 맞춰 상향 | 유니버스가 줄어 결과 변동 |

**A + B를 함께** 하는 것이 맞다고 본다. C·D는 백테스트 기준선을 바꾸므로 별도 승인이
필요하고, 실측상 오염이 없으므로 지금 감수할 이유가 없다.

- 52주 고가·Family D 등 **더 긴 창** criterion의 실측 비율은 아직 안 뽑았다.
  MA200에서만 확인했다.
