## 4. 왜 양성 대조가 못 잡았나 — 이 사고의 핵심 교훈

`[Claude 의견]` 양성 대조는 정상 작동했다. **다른 것을 검사했을 뿐이다.**

    양성 대조가 검사한 것: 재슬라이스 산식 == tape 를 만든 엔진의 산식
    양성 대조가 검사하지 않은 것: 그 tape 가 옳은 tape 인가

운영 tape 와 운영 요약 JSON 은 서로 **완벽히 정합적**이다(|Δ| = 0.00e+00). 폐기된
세대 안에서 자기들끼리 맞는다. 그래서 대조는 통과할 수밖에 없었고, 통과가
**출처에 대해 아무것도 말해주지 않았다.**

> **내부 정합성과 출처는 직교하는 두 축이다. 한쪽 검사가 다른 쪽을 대신하지 못한다.**
>
> 이것은 이 저장소가 이미 일곱 번 잡은 결함과 같은 형태다 — **"없는 것은 오류를
> 내지 않는다"** 의 변종. 여기서 없던 것은 데이터가 아니라 **선언**이었다.
> 기준선이 선언되지 않았으므로 어긋날 수가 없었고, 어긋나지 않으니 조용히 통과했다.
> 대책도 같다: 주장을 산문에서 **실행 시점 검사**로 옮긴다.

08-24 세션이 스스로 잡을 수 있었던 지점은 있었다 — 커버리지 매트릭스가 섀도우
브랜치에만 있다는 사실을 확인했으면서(`git log` 로 커밋 `820a456` 확인), tape 도
같은 브랜치 것이어야 한다는 데까지 잇지 않았다. **한쪽 입력의 출처를 확인했으면
전부 확인해야 한다.**

## 5. 재발 방지 — 구현됨

`[검증된 사실]` 기준선 등록부 `experiments/BASELINES.json` + 강제기
`scripts/analysis/baseline_registry.py`.

- 기준선은 **branch / db_port / artifact_root / commit** 네 가지를 반드시 명시한다.
- 소비 스크립트는 `--baseline` 을 **필수 인자**로 받는다 (생략 불가).
- 선언된 기준선의 **모든 입력 sha256 을 전수 대조**하고, 하나라도 어긋나면
  결과를 산출하지 않고 `BaselineMismatch` 로 중단한다 (fail-closed).
- 기준선 밖 공용 입력은 `compatible_baselines` 로 호환성을 판정한다.
- 결과 JSON 에 `provenance` 블록을 싣는다 — **결과 파일만 보고도 출처를 안다.**
- 폐기된 기준선은 `valid_for_official_numbers: false` 로 표시되고 실행 시 경고한다.
