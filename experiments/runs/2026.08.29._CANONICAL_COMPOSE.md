## §1. 등재 — 왜 이번엔 했는가

`[검증된 사실]` 지난 세션 §1-1 은 4항목 중 **등재 하나만** 미통과였다. 나머지 셋은
통과했다 — 입력 5종 고정·검증, 생성기가 `period_truncation.py`(요약 JSON 계열 아님),
`af529ff` 와 net CAGR **17자리 일치**(서로 다른 세션의 독립 경로).

지난 세션이 **스스로 등재해서 통과시키지 않은 것**이 옳았다. 검사를 통과시키려고
검사 조건을 만드는 것은 이 저장소가 반복해 금지해 온 움직임이다. 사용자 결정을 받고
이 세션에서 수행했다.

`[Claude 의견]` 판정 세탁이 아닌 이유: 이것은 **성적 산출물이지 판정 산출물이 아니다.**
등재해도 G1·G5·G2 판정과 SPEC_15 §7-3 조합표는 하나도 바뀌지 않는다.

### 1-1. `period_set` 명시 — 역산을 폐기했다

역산은 오늘 `cut18.periods` 배열이 남아 있어서 되는 것이다. 그 배열이 없는 소비처에서는
이 산출물이 어느 집합인지 말할 방법이 사라진다. 더 중요한 이유는 **fail-closed 5번이
역산에 의존하게 되기 때문**이다 — 검사가 다른 검사의 부산물에 기대는 구조가 된다.

이름은 손으로 붙이지 않는다. `identify_period_set` 이 sha256 으로 A-0 등재 블록을
역참조하고, **등재되지 않은 집합이면 키 자체를 넣지 않는다.** `full20`(n=20)이 그렇다 —
A-0 에 이름이 없어 필드가 없다. 없는 이름을 지어내지 않는다.

`[검증된 사실]` **순수 추가임을 증명했다**: `period_set` 을 도로 빼면 원본과 바이트
동일하다. diff `26 insertions / 0 deletions`.

### 1-2. 등재 위치

`shared_inputs` 에 넣었다 — `account_coverage_matrix.csv` 와 같은 모양이다(저장소 루트
경로 + sha256 + `compatible_baselines`). 등재 사유를 `_doc` 에 남겼다.

`verify()` 전수 통과. **`operational_20260815` 과 함께 쓰면 기준선 혼입으로 거부되는
것까지 확인했다** — 등재가 실제로 살아 있다는 음성 대조다.

## §2. fail-closed 5종 — **무엇이 발화했는가**

| # | 검사 | 음성 대조에서 발화한 것 |
|---|---|---|
| 1 | 등재부 소속 + sha256 | 미등재 파일 → `등재부에 없다` / 내용 변조 → `sha256 불일치` |
| 1-b | 출처가 폐기 세대를 물고 있는가 | 입력에 `ablation/summary.json` 주입 → `_poisoned_summaries 를 입력으로 물고 있다` |
| 2 | 구간 집합 **sha 역참조** | 블록 삭제 → `period_set 블록이 없다` / sha 손상 → `자기 dates 와 불일치` / **이름만 T19 로 바꿈 → `이름이 내용과 어긋난다`** / 미등재 집합 → `A-0 등재부에 없다` |
| 3 | 구간 수·경계 | `n_periods` 19 → `구간 수 불일치` / `start` 를 2016-04-05 로 → `시작 경계 불일치` |
| 4 | 두 등재 산출물의 F net CAGR | `+1e-9` → `F net CAGR 불일치` |
| **5 (신설)** | **성적·게이트 동일 `period_set.sha256`** | 게이트측 sha 만 교체 → `구간 집합이 다르다` |

### 2-1. 음성 대조의 메타 — 대조가 **그 검사기에 걸려 있는가**

검사가 있다는 것과 검사가 그 대조를 잡고 있다는 것은 다른 사실이다. 검사기를 하나씩
무력화해 대조가 **거부를 멈추는지** 확인했다:

```
_check_registered      → nc1(2건)  SystemExit 사라짐
_check_not_poisoned    → nc1b      SystemExit 사라짐
_check_period_set      → nc2(4건)  SystemExit 사라짐 (하위에서 다른 예외로 터짐)
_check_span            → nc3(2건)  SystemExit 사라짐
_check_cross_value     → nc4       SystemExit 사라짐
_check_same_period_set → nc5       SystemExit 사라짐
```

11건 전부, 자기 검사기를 끄면 거부가 사라졌다. 다른 검사기가 우연히 대신 잡고 있던
대조는 **없다.**

오라클 메타 테스트는 조인 단언(`f'META: {target}'` 필수)으로 붙였다.
`or isinstance(AssertionError)` 형태는 **자기가 잡으려던 것과 같은 결함**이었다.

## §4. 예상과 어긋난 것 — **2건**

### 4-1. 일별 지표는 **두 층이고, 한 층은 T18 에 존재하지 않는다**

`[검증된 사실]` 처음에 일별 블록을 T18 판정값만으로 채웠더니 `pytest` 에서 6건이 깨졌다
(대시보드 4 · 용어사전 2). 기대치를 완화하지 않고 원인을 봤다:

- `af529ff` 의 G5 판정 블록(n=18)은 **일별 MDD·Sharpe 둘뿐**이다
- `daily_mdd_gross`·`gross_cagr`·변동성·CVaR·최악월은 **전 구간(n=20) tape 산출**이고,
  그 구간으로만 존재한다. T18 로 다시 내려면 계산해야 하고 그러면 조립기가 판정기가 된다

그래서 층을 **합치지 않고 나눴다**: 태그 블록은 등재 섀도우 전 구간 산출물을 그대로
옮기고, T18 값은 `judgment_t18` 로 따로 둔다. CANONICAL 성적 표는 `judgment_view()` 로
판정 층만 읽는다.

**T18 일별 net CAGR 은 비워 뒀다.** 전 구간 값으로 채우면 그것이 층 혼입이다. 표에
`—` 와 사유가 함께 뜬다.

부수 효과 하나가 개선이다 — 대시보드가 읽는 일별 통계가 2026-08-15 세대에서
**등재 섀도우 세대로 바뀌었다.**

### 4-2. 용어사전 본문에 폐기 세대 수치가 박혀 있었다

`[검증된 사실]` `dashboard/glossary.py` 의 `mdd_basis` 항목이 `−34.14% / −57.08% /
−58.12%` 를 산문에 박고 있었다. 어느 세대로 전환하든 깨지는 값이다 — 전환이 드러낸
**별개의 결함**이지 전환의 부작용이 아니다.

현행 세대로 고쳤다(구간·gross `−33.02%` / 일별·gross `−56.78%` / 일별·net `−57.82%`).
세 값을 나란히 놓을 수 있는 근거도 본문에 적었다 — 낙폭 구간(2018-05-14 → 2020-03-19)이
판정 구간 안에 통째로 들어 있어 **구간·gross 가 n=18 과 n=20 에서 같다.** 다른 지표는
그렇지 않으니 이 병치를 옮겨 쓰면 안 된다.

같은 항목이 G5 FAIL 을 "채택 보류의 **단독 사유**"라고 적고 있었다. 2026-08 구간 절단
재산출에서 **G1 도 FAIL 로 뒤집혔으므로** 더는 사실이 아니다 — 함께 고쳤다.
