# tests/integrity — 무결성 검사

이 저장소의 다른 테스트 두 종류는 **계산이 맞는가**를 본다.

- `tests/characterization/` — "지금 코드가 이런 답을 낸다"를 기록. 버그를 고치면 정당하게 깨진다.
- `tests/oracle/` · `tests/integration/` — "이 답이 옳다"를 증명. 깨지면 수정이 틀린 것이다.

**무결성 검사는 다른 걸 본다: 산출물과 그걸 가리키는 이름·목록이 서로 안 어긋나는가.**

전략 로직을 계산하지 않는다. `experiments/` 의 파일을 열어 "이름이 약속한 설정과 파일
안의 설정이 같은가", "목록이 가리키는 경로가 실재하는가"만 확인하고 어긋나면 실패시킨다.
**계산은 전부 정상인데 이름·목록만 거짓말하는 상태**를 잡는 그물이다.

## 왜 필요한가 — 2026-08-12 사고

`F_pbr_ma200` 이라는 태그 이름 하나가 종목 수 20짜리 결과와 13짜리 결과를 **둘 다** 가리킬
수 있었다. n=13 으로 운영하면서 n=20 산출물을 읽어, 라이브 매니페스트의 예상 회전율이
92.31% 여야 할 자리에 95.00% 가 기록됐다. **에러는 나지 않았다.**
(경위: `scripts/live/freeze_rebalance.py:148-177` 주석)

2026-08-14 에 같은 종류를 하나 더 찾았다. 대시보드가 구간 CSV 에서 지표를 재계산해
`summary.json` 의 엔진 값을 덮어써, 운영 화면의 `G > D (전체 기여)` 판정 배지가 산출물
기준과 **반대로** 떠 있었다 (화면 7.61% > 7.11% ✅ / 실제 7.80% < 9.54% ❌).

두 사고의 공통점: **조용하다.** 그래서 사람 눈이 아니라 검사가 잡아야 한다.

## 실행

```bash
pytest tests/integrity -q          # DB 불필요, 초 단위로 끝난다
```

산출물이 없는 환경(막 clone 한 개발 PC 등)에서는 해당 검사가 skip 된다 — 산출물 자체가
git 미추적이기 때문이다 (`experiments/README.md`). **skip 은 통과가 아니다.** 배포 전
판정은 산출물이 실재하는 서버에서 돌린 결과로 한다.
